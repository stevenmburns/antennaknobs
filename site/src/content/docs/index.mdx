  **Pattern charts: ARRL, EZNEC or linear.** Choose the polar chart's scale.
  ARRL's rings sit 3, 6, 9, 12, 18 and 24 dB down, EZNEC's 5, 10, 15, 20 and

  Thanks to Dan, AC6LA. See
  [Pattern scale](/reference/web/#pattern-scale--arrl-eznec-or-linear).

  **Watch the optimizer, and stop it when you like.** A marked knob shows the
  value being tried under itself while a run goes. Turning Optimize off
  mid-run cancels it and asks whether to keep the best point so far or the
  start. See [Optimizing](/reference/web/#optimizing).

  **A transmission line takes its numbers by name** (momwire 0.86.0). Write
  `TL("rig", "feed", z0=50, length=10, vf=0.82, k1=0.27, k2=0.0055)`. Every
  number after the two port names now has to be named, because a call that
  listed them in another order used to solve the wrong cable without a word.
  A design that passes them by position stops with a message naming the call:
  add the names.

  **Open your own design `.py`.** **Open…** now takes an antennaknobs design
  file as well as a deck. Its code runs in a separate, locked-down process,
  and only its wires and network come back. The hosted app opens one only
  where that process is also cut off from the network and the server's files.
  See [A design .py](/reference/web/#a-design-py).

## The whole pitch, in one line

antennaknobs describes an antenna **as Python code** — a small parametric
*builder*, its geometry computed from named knobs — then lets you explore it two
ways: drive it from a script (sweep, optimize, compare, export a NEC deck), or
open it in a browser and **turn the knobs live**, watching the radiation
pattern, SWR, and impedance respond as you drag. Most antenna tools are a static
formula calculator or a desktop app you have to install; this is neither.
