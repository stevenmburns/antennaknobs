142# Two-wire line geometry: physical stock → the electrical numbers a 

143# `BalancedLine` takes. Moved here from `network.py` in momwire#456 ws2 phase

148# Free-space wave impedance, √(μ₀/ε₀). The two-wire line formula below is 

149# η₀/π ≈ 119.917 Ω per unit of acosh — the familiar "276·log₁₀(2D/d)" of the 

150# handbooks is this same constant in base-10 clothing. 

151ETA0 = 376.730313668

164def two_wire_params( 

165 spacing: float, 

166 radius: float, 

167 radius2: float | None = None, 

168 *, 

169 insulation_radius: float | None = None, 

170 eps_r: float | None = None, 

171 fill: float | None = None, 

172) -> tuple[float, float]: 

173 """``(zdiff, vf)`` of a two-conductor line from its physical dimensions 

174 (issue #596). 

175 

176 ``spacing`` is centre-to-centre, ``radius``/``radius2`` are the conductor 

177 radii (``radius2=None`` → equal conductors); all lengths in metres, to 

178 match the rest of the package. Use it when you know the *line* — "#14 

179 wire, six inches apart" — rather than the number off a spool: 

180 

181 zdiff, vf = two_wire_params(0.1524, 0.000815) # ≈ 627 Ω, 1.0 

182 

183 **Bare conductors** are exact, from the general unequal-radius form 

184 

185 Z = (η₀/2π)·acosh((D² − a₁² − a₂²) / (2·a₁·a₂)) 

186 

187 which collapses to the textbook ``(η₀/π)·acosh(D/d)`` for equal radii 

188 (evaluated in that direct form when the radii match, which is both exactly 

189 the identity ``acosh(2x²−1) = 2·acosh(x)`` and better conditioned for 

190 closely-spaced wires). 

191 

192 **Insulation** is where the honesty caveats live, because a real balanced 

193 line is a *partial* dielectric fill — some of the field is in the plastic, 

194 most is in the air — and no closed form covers every construction. Two 

195 documented estimators, both reducing the result by ``√ε_eff`` (the 

196 inductance is unchanged: the jacket is not magnetic), so 

197 ``vf = 1/√ε_eff``: 

198 

199 - ``insulation_radius`` + ``eps_r`` — the **coaxial-shell** model: each 

200 conductor wears a jacket of outer radius ``b``, and the potential 

201 integral splits into a dielectric part ``(1/εᵣ)·ln(b/a)`` and an air part 

202 ``ln(D/b)``. Right for jacketed wire and for window line, where the 

203 conductors are round, jacketed, and separated by mostly air. It uses the 

204 wide-spacing (``D ≫ b``) logarithmic form for the *correction only* — the 

205 bare value it corrects stays exact — and it is refused outright when the 

206 jackets touch (``b₁ + b₂ ≥ D``), where the assumption of air between them 

207 is simply false. 

208 - ``fill`` + ``eps_r`` — the **mixing rule** ``ε_eff = 1 + fill·(εᵣ − 1)`` 

209 for the constructions the shell model can't describe: solid-web twinlead, 

210 or windowed line whose webbing you want to account for empirically. 

211 ``fill`` is the fraction of the field energy sitting in dielectric, and 

212 it is a fitted number, not a derived one (≈0.5 for solid twinlead, 

213 ≈0.15–0.25 for windowed line). Supply it when you have a nameplate ``vf`` 

214 to match; prefer the shell model when you don't. 

215 

216 Manufacturers' "450 Ω" and "300 Ω" are round numbers over a range of real 

217 constructions, so expect geometry-derived values to land within a few 

218 percent of a nameplate, not on it. When you know the nameplate ``vf``, 

219 it is better data than either estimator here. 

220 """ 

221 a1 = float(radius) 

222 a2 = float(radius if radius2 is None else radius2) 

223 d = float(spacing) 

224 if a1 <= 0 or a2 <= 0: 

225 raise ValueError("conductor radii must be positive") 

226 if d <= a1 + a2: 

227 raise ValueError( 

228 f"centre spacing {d} m must exceed the sum of the radii " 

229 f"({a1 + a2} m) — these conductors overlap" 

230 ) 

231 

232 if a1 == a2: 

233 z_bare = (ETA0 / math.pi) * math.acosh(d / (2.0 * a1)) 

234 else: 

235 z_bare = (ETA0 / (2.0 * math.pi)) * math.acosh( 

236 (d * d - a1 * a1 - a2 * a2) / (2.0 * a1 * a2) 

237 ) 

238 

239 eps_eff = 1.0 

240 if fill is not None: 

241 if eps_r is None: 

242 raise ValueError("fill needs eps_r (the insulation's permittivity)") 

243 if not 0.0 <= fill <= 1.0: 

244 raise ValueError(f"fill must be a fraction in [0, 1]; got {fill}") 

245 eps_eff = 1.0 + fill * (float(eps_r) - 1.0) 

246 elif insulation_radius is not None: 

247 if eps_r is None: 

248 raise ValueError("insulation_radius needs eps_r") 

249 b = float(insulation_radius) 

250 b1 = b2 = b 

251 if b1 <= a1 or b2 <= a2: 

252 raise ValueError( 

253 f"insulation radius {b} m must exceed the conductor radius" 

254 ) 

255 if b1 + b2 >= d: 

256 raise ValueError( 

257 f"the jackets touch at this spacing ({b1 + b2} m of insulation " 

258 f"across a {d} m gap): there is no air path between the " 

259 "conductors, so the coaxial-shell model does not apply. Give " 

260 "`fill` (with eps_r) for a solid-web line, or pass the " 

261 "nameplate zdiff/vf directly." 

262 ) 

263 er = float(eps_r) 

264 bare_terms = math.log(d / a1) + math.log(d / a2) 

265 clad_terms = ( 

266 math.log(b1 / a1) / er 

267 + math.log(d / b1) 

268 + math.log(b2 / a2) / er 

269 + math.log(d / b2) 

270 ) 

271 eps_eff = bare_terms / clad_terms 

272 

273 return z_bare / math.sqrt(eps_eff), 1.0 / math.sqrt(eps_eff)

276def balanced_line_from_geometry( 

277 a1, 

278 a2, 

279 b1, 

280 b2, 

281 *, 

282 spacing, 

283 length, 

284 conductor, 

285 conductor2=None, 

286 eps_r=None, 

287 fill=None, 

288 k1=0.0, 

289 k2=0.0, 

290 zcomm=None, 

291): 

292 """A `BalancedLine` whose ``zdiff``/``vf`` come from the line's physical 

293 dimensions instead of a spool label (issue #596). 

294 

295 ``conductor`` (and ``conductor2`` for an unequal pair) is a radius in 

296 metres, a `WireSpec`, or a `WIRES` catalog key — so a jacketed catalog 

297 wire brings its own insulation along:: 

298 

299 balanced_line_from_geometry( 

300 "t1", "t2", "a1", "a2", 

301 spacing=0.0254, length=20.0, conductor="18-awg-pvc", 

302 ) 

303 

304 ``spacing`` is centre-to-centre in metres. See :func:`two_wire_params` 

305 for the electrical model and, importantly, for what the insulation 

306 estimators can and cannot claim. ``k1``/``k2``/``zcomm`` pass straight 

307 through — geometry says nothing about matched loss or the common-mode 

308 path, which stay explicit. 

309 

310 A plain function rather than ``BalancedLine.from_geometry`` (momwire#456 

311 ws2): the class lives in momwire now and has no catalog to resolve 

312 ``conductor`` against, so the constructor stays where `WIRES` is. 

313 """ 

314 r1, ins1, er1 = _conductor_geometry(conductor) 

315 r2, ins2, er2 = ( 

316 (None, None, None) if conductor2 is None else _conductor_geometry(conductor2) 

317 ) 

318 if ins1 is not None and ins2 is not None and ins1 != ins2: 

319 raise ValueError( 

320 "the two conductors declare different insulation radii " 

321 f"({ins1} vs {ins2} m); the shell model assumes one jacket " 

322 "thickness — pass `fill` (with eps_r) instead" 

323 ) 

324 insulation_radius = ins1 if ins1 is not None else ins2 

325 eps_r = eps_r if eps_r is not None else (er1 if er1 is not None else er2) 

326 zdiff, vf = two_wire_params( 

327 spacing, 

328 r1, 

329 r2, 

330 insulation_radius=insulation_radius, 

331 eps_r=eps_r, 

332 fill=fill, 

333 ) 

334 return BalancedLine( 

335 a1=a1, a2=a2, b1=b1, b2=b2, zdiff=zdiff, length=length, 

336 vf=vf, k1=k1, k2=k2, zcomm=zcomm, 

337 ) # fmt: skip

340class Wire(NamedTuple): 

341 """One ``build_wires()`` entry, named (issue #388). A drop-in superset 

342 of the plain-tuple contract: a ``Wire`` IS a tuple, so indexing, 

343 unpacking, and the ``t[4]``-style name access keep working, and designs 

344 may freely mix plain 4/5-tuples and ``Wire`` entries in one list. 

345 

346 With every field after the endpoints defaulted, keyword construction 

347 is the recommended brief spelling — ``Wire(a, b)`` is a structural 

348 wire at the design density, ``Wire(t, s, ex=1 + 0j)`` the feed, 

349 ``Wire(ti, to, name="trap_b0")`` a named attachment wire — with no 

350 positional ``None`` placeholders. (Plain tuples stay 4-6 fields; 

351 short plain tuples are rejected because a bare third element would 

352 be ambiguous between a count and an excitation.) 

353 

354 ``n_seg=None`` means "mesh me at the design density" — resolved by 

355 ``AntennaBuilder.auto_mesh`` as part of the stack (nominal_nsegs 

356 segments per design_freq quarter-wave); an integer is honored 

357 verbatim. ``n_seg`` may also be a :class:`GradedSegments` (a wire 

358 meshed geometrically toward one end) — always built via 

359 :func:`graded_wire`, never by hand; generic consumers doing 

360 ``int(w[2])`` arithmetic must treat that case (isinstance-check it) 

361 or refuse it by name. 

362 

363 ``spec=None`` means "the design default": engines fall back to 

364 ``build_wire_material()``. Precedence, defined once: an explicit 

365 per-wire ``spec`` wins; the web ``wire_radius`` override only moves 

366 the default. Transforms, array placement, and scale knobs never scale 

367 a ``spec`` — it describes the physical wire stock the antenna is 

368 built from, not the geometry. 

369 """ 

370 

371 p0: tuple 

372 p1: tuple 

373 n_seg: int | None = None 

374 ex: complex | None = None 

375 name: str | None = None 

376 spec: WireSpec | None = None

379class GradedSegments(NamedTuple): 

380 """``n_seg`` spelling for a wire meshed geometrically toward one end 

381 (momwire#674's node-grading recipe, promoted to a first-class 

382 spelling by the buried-radial default-mesh fix). 

383 

384 The wire stays ONE ``build_wires()`` entry and ONE polyline edge 

385 chain: `flat_wires_to_polylines` expands it into interior vertices 

386 with per-edge counts INSIDE its polyline, so grading can never 

387 change the junction topology — the defect hand-split wires have on 

388 coincident bundles, where every shared split point mints a spurious 

389 KCL row (measured on the buried screen: 8-member junctions at every 

390 graded vertex). 

391 

392 ``fracs``: interior vertex positions as fractions of the wire length 

393 measured from ``p0``, strictly increasing in (0, 1). ``counts``: 

394 per-sub-edge segment counts, ``p0 → p1`` order, one longer than 

395 ``fracs``. Build these with :func:`graded_wire` rather than by hand. 

396 

397 A graded wire is structural only — the geometry walk rejects one 

398 carrying an excitation or a port name (a delta gap inside a graded 

399 chain would re-mesh the feed model; see the buried-radial builder's 

400 feed-gap note). 

401 

402 SCOPE-FROZEN (maintainer decision, 2026-08-28, PR #1024): this 

403 spelling has ONE consumer (the buried-radial vertical's default 

404 mesh) and stays exactly this size until a second consumer exists. 

405 Extensions each have a recorded unfreeze trigger — card-engine 

406 expansion via :meth:`subdivide` (a graded design needing NEC 

407 export), bend-grading (someone chasing the measured hub-bend 

408 0.1–0.2 Ω class), momwire-side knot multiplicity (a second 

409 slope-freedom consumer; momwire#449's closure records it) — and 

410 every unfreeze starts with a named consumer, an issue, and a 

411 measurement, in that order. Do not grow this spelling ahead of 

412 that. 

413 """ 

414 

415 fracs: tuple 

416 counts: tuple 

417 

418 def subdivide(self, p0, p1): 

419 """Expand to explicit ``(q0, q1, n)`` sub-wires — for card-based 

420 consumers (the .nec exporter) where per-wire uniform segment 

421 counts are the native spelling anyway.""" 

422 import numpy as _np 

423 

424 a = _np.asarray(p0, dtype=float) 

425 b = _np.asarray(p1, dtype=float) 

426 cuts = [a] + [a + f * (b - a) for f in self.fracs] + [b] 

427 return [ 

428 (tuple(q0), tuple(q1), int(n)) 

429 for (q0, q1), n in zip(itertools.pairwise(cuts), self.counts, strict=True) 

430 ]

433def graded_wire( 

434 p0, 

435 p1, 

436 *, 

437 toward, 

438 h_node=0.0125, 

439 growth=4.0, 

440 per_panel=2, 

441 rest_h=None, 

442 name=None, 

443 spec=None, 

444) -> Wire: 

445 """A structural wire graded toward one end (``toward`` = ``"p0"`` or 

446 ``"p1"``): panel boundaries at ``h_node * growth**k`` from the graded 

447 end (the #674 recipe — its defaults reproduce the measured-converged 

448 6.25 mm node mesh: boundaries 12.5 mm, 50 mm, … capped at the wire 

449 length), ``per_panel`` segments per panel. ``rest_h`` (metres), when 

450 given, meshes the final far panel at that segment length instead — 

451 pass the design's own segment length so a long wire's far end stays 

452 at catalog density. 

453 """ 

454 import math as _math 

455 

456 length = _math.dist(tuple(p0), tuple(p1)) 

457 if toward not in ("p0", "p1"): 

458 raise ValueError(f"toward must be 'p0' or 'p1', got {toward!r}") 

459 if not 0 < h_node < length: 

460 raise ValueError(f"h_node {h_node} outside (0, wire length {length:.4g})") 

461 bounds = [] 

462 b = h_node 

463 while b < length * (1 - 1e-9): 

464 bounds.append(b) 

465 b *= growth 

466 counts = [per_panel] * (len(bounds) + 1) 

467 if rest_h is not None: 

468 rest_len = length - (bounds[-1] if bounds else 0.0) 

469 counts[-1] = max(per_panel, round(rest_len / rest_h)) 

470 if toward == "p1": 

471 fracs = tuple(1.0 - b / length for b in reversed(bounds)) 

472 counts = list(reversed(counts)) 

473 else: 

474 fracs = tuple(b / length for b in bounds) 

475 return Wire( 

476 tuple(p0), 

477 tuple(p1), 

478 n_seg=GradedSegments(fracs=fracs, counts=tuple(int(c) for c in counts)), 

479 name=name, 

480 spec=spec, 

481 )

500def validate_named_wires_referenced(named_wires, network): 

501 """Reject named ``build_wires()`` wires that no `PortOnWire` references 

502 (issue #578). 

503 

504 The geometry layer registers EVERY named wire as a port edge; a port row 

505 the network never references is left electrically open, and an open 

506 series gap CUTS the current path at that wire. The failure is silent and 

507 masquerades as plausible physics (the solve succeeds with the structure 

508 partitioned), so it is an init-time error. A wire named purely for 

509 documentation is almost certainly this bug; a deliberately-open gap 

510 should be an explicit `Load`/branch on a referenced port. 

511 

512 Engines call this once the flattened network and the final wire list are 

513 both known (composite expansion has already namespaced port names). 

514 """ 

515 # The port types are imported at module scope (from momwire.networks — 

516 # see the header). Until momwire#456 ws2 phase B they had to be imported 

517 # here at CALL time, because they lived in `antennaknobs.network`, which 

518 # imports this module for its compatibility re-exports; the circuit half 

519 # moving down dissolved that cycle. 

520 gap_names = {n for n, p in network.ports.items() if isinstance(p, PortOnWire)} 

521 # End and vertex ports both name geometry without cutting a gap, so 

522 # they share one rule against gap ports (a wire may carry BOTH an end 

523 # and a vertex port — on different or even the same endpoint, where 

524 # momwire's own shunt+series conflict rule then applies). 

525 end_names = { 

526 p.wire 

527 for p in network.ports.values() 

528 if isinstance(p, (PortAtEnd, PortAtVertex)) 

529 } 

530 both = sorted(gap_names & end_names) 

531 if both: 

532 raise ValueError( 

533 f"wire name(s) {both} are referenced by both a PortOnWire and a " 

534 "PortAtEnd/PortAtVertex — a gap port cuts a delta gap in the " 

535 "wire while an end or vertex port must leave it gapless " 

536 "(issues #579, #898); use separate wires." 

537 ) 

538 orphaned = sorted(set(named_wires) - {None} - gap_names - end_names) 

539 if orphaned: 

540 raise ValueError( 

541 f"named wire(s) {orphaned} are not referenced by any PortOnWire, " 

542 "PortAtEnd or PortAtVertex in build_network(); a named wire " 

543 "becomes a port edge, and an unreferenced port is an OPEN gap " 

544 "that cuts the wire there (issue #578). Reference each name in " 

545 "Network.ports, or drop the name." 

546 )
