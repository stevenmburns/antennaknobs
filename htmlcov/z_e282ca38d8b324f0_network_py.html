1"""Port-based network spec for transmission lines and lumped elements. 

2 

3A `Network` describes how the antenna's feed-edges (named real ports) and 

4purely-logical nodes (virtual ports) hook together via two-port branches. 

5Engines consume the network as a post-processing layer on top of the 

6multi-port antenna Y matrix: every branch and source stamps into one 

7Modified Nodal Analysis system (see `network_reduce`), which is solved for 

8the driven-port impedances and the physical port voltages in one shot. 

9 

10Compared with the legacy `build_tls()` API: 

11 - No dummy stub wire is required for the driver — virtual ports exist 

12 only in the network reduction, not in the geometry. 

13 - Branches refer to ports by name; no manual segment-index counting. 

14 - Same shape covers transmission lines (`TL`) and (planned) lumped 

15 elements (`Load`, `TwoPort` — coming in a follow-up). 

16 

17For PyNECEngine, this spec gets translated back into the NEC2-shaped 

18`tl_card` / `ld_card` / `nt_card` calls, with virtual ports synthesised 

19as tiny stub wires at sensible locations. 

20"""

31@dataclass(frozen=True) 

32class PortOnWire: 

33 """Real port ON a named wire of the geometry: `name` matches the label 

34 a `build_wires()` tuple carries as its 5th element, and the port is a 

35 delta gap at that wire's MIDDLE segment (momwire: the arclength 

36 midpoint; PyNEC: segment (n_seg+1)//2 — identical placement for odd 

37 segment counts, which named port wires should therefore use). A port 

38 must interrupt a current path, so it lives in a wire's interior, never 

39 at an endpoint — to put a feed "at" some point of a structure, author 

40 a short named wire there. 

41 

42 This is the only port type that touches geometry (contrast 

43 `PortVirtual`, a pure circuit node): it becomes one row/column of the 

44 antenna's multiport short-circuit Y that the network stamps onto. 

45 

46 ``distributed=True`` makes the port a FINITE gap spanning the whole 

47 named wire instead of a delta gap on one segment: the excitation is a 

48 constant field over the wire's fixed physical length (one sub-feed per 

49 segment, voltages split by length), and the port row of Y is the 

50 length-weighted contraction of the sub-feed rows. A delta gap's 

51 readout moves whenever mesh refinement subdivides the port wire (the 

52 gap narrows with the segment — issue #477's port-drift class: 

53 sterba_tl's pinned ports, zepp's jump when its port wire first 

54 subdivides); the finite gap's width is set by geometry, not by the 

55 mesh, so the port impedance is mesh-stable by construction and the 

56 port wire may refine like every other wire. The value it converges to 

57 is the finite-gap answer for THAT physical width — for the short port 

58 stubs this models, within a couple percent of the delta-gap limit, 

59 and (unlike the pinned delta gap) basis-independent. 

60 

61 Formerly `PortAtEdge` ("edge" in the wire-graph sense, which read as 

62 "wire end"); that name remains as a deprecated alias.""" 

63 

64 name: str 

65 distributed: bool = False

77@dataclass(frozen=True) 

78class PortOnWireFloating(PortOnWire): 

79 """A `PortOnWire` whose BOTH terminals are exposed as circuit nodes. 

80 

81 An ordinary gap port is stamped node-to-datum: its second terminal is 

82 bonded to the common return, so a branch can only connect to one side of 

83 the gap. That is a *stamping convention*, not physics — the MoM only ever 

84 knows gap voltage and gap current, so every delta gap is inherently a 

85 floating two-terminal object. This port type stops imposing the bond. 

86 

87 The two terminals are addressed as dotted sub-nodes — ``"feed.p"`` and 

88 ``"feed.n"`` for a port named ``feed`` — the same way `Instance` exposes a 

89 composite's interior nodes (``"tuner.m"``). Branches reference those names; 

90 the bare port name is not a node. 

91 

92 Use it to hang a genuinely balanced element off the structure: the two 

93 terminals may go to *different* branches, which a node-to-datum port 

94 cannot express. SimNEC models NEC feeds this way as a matter of course — 

95 its `NECSource({w1,w2}, wire, percent)` takes two arbitrary circuit nets, 

96 and its Ruthroff/Guanella balun sample runs the two sides of one antenna 

97 gap into two different choke inductors. 

98 

99 Unlike `PortAtEnd` this needs nothing new from the solver — it changes only 

100 how the shared reducer stamps the antenna's multiport Y — so it works on 

101 every engine, PyNEC included. 

102 

103 NOTE a single floating gap is a 1-port: its Y has one degree of freedom, so 

104 the stamp is purely differential and supplies NO common-mode path. Either 

105 give the network a CM return, or model the CM path as its own gap port — 

106 a 2-port Y couples the two gaps and carries that physics itself. 

107 """

116@dataclass(frozen=True) 

117class PortAtEnd: 

118 """Port AT a wire ENDPOINT (issue #579) — the attachment a floating 

119 multi-terminal element (`BalancedLine`) needs and a `PortOnWire` gap 

120 cannot provide (a gap is a series insertion; issue #576's validation 

121 mapped the dead-end-stub and bridge-idiom failure modes). 

122 

123 ``wire`` names a `build_wires()` tuple (names must be unique); ``end`` 

124 picks its authored ``"p0"`` or ``"p1"`` endpoint. The port resolves to 

125 the shared NODE at that point: geometry translation forces a polyline 

126 boundary there and momwire hosts a junction port (momwire#172) — the 

127 node's KCL row becomes the port's drive/readout vector, so driving the 

128 port injects current INTO the node and the port voltage is the node's 

129 Lagrange dual. When several wire ends coincide at the point, the port 

130 attaches to the whole shared junction group (declare it on ONE of the 

131 wires). Unlike `PortOnWire`, no gap is cut in the wire — the name only 

132 identifies the geometry, and a wire name may be referenced by either 

133 port kind, not both. 

134 

135 momwire-only: NEC-2 has no junction-node port (NT/TL cards attach to 

136 segment interiors), so `PyNECEngine` rejects designs using this port 

137 type — a deliberate, declared engine-parity break."""

151class TL: 

152 """Transmission line between two ports — lossless by default, lossy when 

153 matched-loss coefficients are given (issue #297). 

154 

155 z0: characteristic impedance in Ω 

156 length: physical length in meters 

157 

158 The electrical length βl is computed at solve time from the antenna's 

159 operating wavelength and `vf`. Both endpoints can be either real or 

160 virtual. 

161 

162 transposed: crossed ("half-twist") line — inverts port B's polarity, 

163 flipping the sign of the off-diagonal transfer terms. This is the 

164 phase reversal a transposed-feeder array (LPDA, ZL-Special) needs. 

165 Prefer it over a negative z0, which would wrongly negate the diagonal 

166 self terms too. 

167 

168 vf: velocity factor — phase velocity as a fraction of c, so 

169 β = 2π/(vf·λ₀). The default 1.0 preserves the historical behavior 

170 (physical length read as free-space electrical length). 

171 

172 k1, k2: matched-loss coefficients in the cable-table convention, 

173 matched loss [dB per 100 ft] = k1·√f_MHz + k2·f_MHz 

174 (k1 = conductor/skin-effect term, k2 = dielectric term). α is derived 

175 from these at each operating frequency, so sweeps get the loss slope 

176 for free, and SWR-dependent additional loss emerges from the circuit 

177 solution rather than a formula. Defaults 0.0 → lossless. Use 

178 `TL.from_cable()` for real cables. 

179 """ 

180 

181 a: str # port name 

182 b: str 

183 z0: float 

184 length: float 

185 transposed: bool = False 

186 vf: float = 1.0

188 k2: float = 0.0

301class Wire(NamedTuple): 

302 """One ``build_wires()`` entry, named (issue #388). A drop-in superset 

303 of the plain-tuple contract: a ``Wire`` IS a tuple, so indexing, 

304 unpacking, and the ``t[4]``-style name access keep working, and designs 

305 may freely mix plain 4/5-tuples and ``Wire`` entries in one list. 

306 

307 With every field after the endpoints defaulted, keyword construction 

308 is the recommended brief spelling — ``Wire(a, b)`` is a structural 

309 wire at the design density, ``Wire(t, s, ex=1 + 0j)`` the feed, 

310 ``Wire(ti, to, name="trap_b0")`` a named attachment wire — with no 

311 positional ``None`` placeholders. (Plain tuples stay 4-6 fields; 

312 short plain tuples are rejected because a bare third element would

316 ``AntennaBuilder.auto_mesh`` as part of the stack (nominal_nsegs

318 verbatim. 

319

321 ``build_wire_material()``. Precedence, defined once: an explicit 

322 per-wire ``spec`` wins; the web ``wire_radius`` override only moves 

323 the default. Transforms, array placement, and scale knobs never scale 

324 a ``spec`` — it describes the physical wire stock the antenna is 

325 built from, not the geometry. 

326 """

354@dataclass(frozen=True) 

355class Load: 

356 """R/L/C load inserted in series with a single segment's current path. 

357 

358 `parallel=False` (default): series R + jωL + 1/(jωC). The whole expression 

359 is a single series impedance Z_load that adds to the segment's MoM Z[k,k]. 

360 NEC2 calls this `ld_card` type 0. 

361 

362 `parallel=True`: parallel R || jωL || 1/(jωC). The branch's effective 

363 series impedance Z_load = 1 / (1/R + 1/(jωL) + jωC). At ω₀ = 1/√(LC) 

364 the parallel-LC has Y → 0 → Z_load → ∞, which is exactly the trap idiom: 

365 the segment's current is interrupted at the trap's resonant frequency. 

366 NEC2 calls this `ld_card` type 1. 

367 

368 Either way the effect is "lumped impedance in series with the segment": 

369 in the MNA reduction the load becomes the port's termination branch, a 

370 series Z_load between the segment's gap and the common return — the same 

371 physics as NEC2's ld_card modifying the segment's self-Z. The classic 

372 dual-band trap dipole uses Load(parallel=True) at a single segment in 

373 each arm — see designs/multiband/trap_dipole.py. 

374 

375 `z` sets a FIXED, frequency-independent series impedance R + jX directly 

376 (NEC2 `ld_card` type 4, issue #422): unlike the R/L/C legs whose reactance 

377 scales with ω, `z` is used verbatim at every frequency. It is mutually 

378 exclusive with r/l/c/parallel/ql/qc — a load is either the RLC form or the 

379 fixed-Z form, never both. The reactive counterpart to `Admittance` for the 

380 *series* (in-the-current-path) case, where a shunt would be wrong. 

381 """ 

382 

383 port: str 

384 r: float | None = None 

385 l: float | None = None 

386 c: float | None = None 

387 parallel: bool = False 

388 ql: float | None = None # coil Q: adds series R = omega*L/Q (issue #298) 

389 qc: float | None = None # capacitor Q: adds ESR = 1/(omega*C*Q) 

390 z: complex | None = None # fixed R+jX series impedance (ld_card 4, #422)

406 """Lumped series R+jωL+1/(jωC) bridging two ports. Any of r/l/c may be

420 stamp, analogous to `tl_card` for TL. The showcase and cross-engine 

421 cross-check is `designs/arrays/lumped_coupled_pair.py` (issue #65 piece

471@dataclass(frozen=True) 

472class Transformer: 

473 """Ideal transformer between two ports, with optional loss — the 

474 balun/unun element (issue #301). Each winding spans its port's node to 

475 the common datum (the same two-terminal convention every branch uses). 

476 

477 n is the a:b turns ratio: v_a = n·v_b and i_b = −n·i_a, so the 

478 impedance seen at port a is n²·Z_b — a 4:1 balun stepping a ~300 Ω 

479 folded-dipole feed down to ~75 Ω line is `Transformer(a=line_side, 

480 b=feed, n=0.5)`. n = 1 (with no loss) is an ideal through-connection; 

481 n = 0 is rejected at stamp time (it would pin v_a = 0 while 

482 open-circuiting b — no physical transformer does that). 

483 

484 Loss model, deliberately minimal (enough to reproduce a published 

485 insertion-loss curve's shape, not a full transformer model): 

486 r — series winding resistance in Ω, referred to side a 

487 (constitutive row v_a − n·v_b = r·i_a); 

488 lmag — magnetizing inductance in H, shunted across side a: at low 

489 frequency ωL_mag stops dwarfing the source impedance and 

490 insertion loss rises, the classic balun low-end rolloff; 

491 qlmag — finite Q of the magnetizing branch (core loss), same 

492 convention as `ql` elsewhere (issue #298). 

493 

494 Reducer-only on both engines: there is no native NEC card for an 

495 ideal transformer (nt_card could bake a lossy 2×2 but not the ideal 

496 ratio), so a Transformer always takes the shared MNA path. Its 

497 dissipation (winding + magnetizing) itemizes in the power budget 

498 (issue #299).""" 

499 

500 a: str 

501 b: str 

502 n: float 

503 r: float | None = None 

504 lmag: float | None = None 

505 qlmag: float | None = None

507 #: ``lmag``/``qlmag`` wholesale — it is the core, not a default, exactly as 

508 #: ``TL.from_cable``'s cable is the cable. The magnetizing branch then 

509 #: follows the mix's complex permeability at each frequency: μ′ sets the 

510 #: inductance, μ″ the loss, and the effective Q (μ′/μ″) moves with 

511 #: frequency the way a real choke's does.

517 """Tapped single winding — the auto-transformer (issue #594). 

518 

519 `Transformer` is an *isolation* transformer: two windings, coupled only by 

520 the core. An autotransformer has **one** winding with a tap, so primary and 

521 secondary are galvanically connected and share the common turns. That is 

522 not a detail of construction — it changes the constitutive law, because the 

523 current in the common section is the *difference* of the input and output 

524 currents rather than a ratio-scaled copy. 

525 

526 So this is not modelled as an ideal ratio. It is two **mutually coupled 

527 inductors** in series up one leg: 

528 

529 datum ──[ l_lower ]── a (tap) ──[ l_upper ]── b (top) 

530 

531 with mutual ``M = k·√(l_lower·l_upper)`` between them, stamped as two 

532 Group-2 branch-current rows plus their off-diagonal coupling. The turns 

533 ratio, the magnetizing behaviour, and the loss all fall *out* of that L/M 

534 matrix instead of being asserted — which is the point: an ideal-ratio model 

535 would get the common-section current wrong. 

536 

537 In the ideal limit (``k`` → 1, inductances ≫ the load reactance) it 

538 reproduces the textbook tapped ratio 

539 

540 n = 1 + √(l_upper / l_lower) (turns go as √L on one core) 

541 

542 so the impedance at the tap is the load at the top divided by n² — 

543 :func:`~antennaknobs.station.autotransformer_ratio` computes it. 

544 

545 ``ql`` gives both sections the same finite Q (core + winding loss as a 

546 series r = ωL/Q, the ``ql`` convention used elsewhere); it itemizes in the 

547 power budget as *resistive* dissipation only, never the reactive power the 

548 two windings exchange. 

549 

550 ``k`` must satisfy 0 ≤ k ≤ 1. Above 1 the inductance matrix stops being 

551 positive semi-definite — M² > L₁L₂ means the pair can deliver more energy 

552 than it stores — and the element would quietly generate power. SimSmith 

553 permits it and calls it non-physical; we refuse it, because our power 

554 budget claims to balance. 

555 

556 Reducer-only, like `Transformer`: no NEC card, both engines. 

557 """ 

558 

559 a: str # the tap — the low-impedance side 

560 b: str # the top of the winding — the high-impedance side 

561 l_lower: float # henries, datum → tap (the common section) 

562 l_upper: float # henries, tap → top

653@dataclass(frozen=True) 

654class BalancedLine: 

655 """Balanced / differential two-conductor transmission line (issue #575) — 

656 the differential sibling of `TL`. Where a `TL(a, b)` is single-ended (each 

657 end referenced to the one network common), a BalancedLine models a pair of 

658 conductors carrying ±I with the return current riding the *partner* wire: 

659 open-wire feeder, twisted pair, the Sterba curtain's offset-pair verticals. 

660 

661 Four terminals in two pairs — port A = ``(a1, a2)``, port B = ``(b1, b2)``, 

662 the two ends of the 2-conductor line. It is characterised by a single 

663 **differential impedance ``zdiff``** (the number off the ladder-line spool: 

664 300 / 450 / 600 Ω) plus physical ``length``, ``vf``, and optional 

665 matched-loss ``k1``/``k2`` — mirroring `TL`. For anyone coming from the 

666 microwave even/odd convention, ``zdiff = 2·z0o``. 

667 

668 **Differential by default, with an optional common-mode path** (``zcomm``, 

669 issue #576). The default ``zcomm=None`` stamps only the odd-mode block, 

670 which structurally forces ``I(a1) = −I(a2)`` at each end — exactly the ±I 

671 cancellation the Sterba pair relies on, enforced by construction. That 

672 default follows the physics of an isolated pair: it supports exactly one 

673 TEM mode (the differential one); the even ("common") mode's return is a 

674 third conductor that isn't there, its Z0 is ill-defined, and even-mode 

675 current is really antenna-mode current that radiates, which a network 

676 branch cannot faithfully represent. 

677 

678 BUT — the #576 end-to-end finding — a differential-only stamp also 

679 deletes the pair's *conductor continuity*: a real pair, however tightly 

680 coupled, still transports its end-to-end common-mode boundary condition, 

681 and in multi-loop structures (the multi-bay Sterba curtain) that 

682 constraint is load-bearing even where the CM *current* is small (measured 

683 5–15% of DM there, yet its removal costs 5 dB and steers the beam). Set 

684 ``zcomm`` — the pair-driven-as-one-conductor CM impedance — to add the 

685 orthogonal even-mode block and restore the path. Honesty notes: at 

686 resonant lengths (≈ k·vf·λ/2, e.g. the Sterba's risers) the CM line is a 

687 repeater and results are insensitive to the value (measured identical 

688 over 25–400 Ω), so any plausible number is fine; away from resonance 

689 ``zcomm`` is a genuine approximation for a radiating path — estimate it 

690 from geometry and treat results accordingly. The CM stamp still cannot 

691 radiate; a structure whose riser antenna-mode current matters beyond its 

692 boundary condition needs real wires. 

693 

694 Stamped through the shared `NetworkReducer` as one chain-matrix 2-port 

695 per mode (issue #746): in differential variables it is an ordinary 2-port 

696 TL with z0 = zdiff, carried on the pair incidence (+1, −1) at each end; 

697 ``zcomm`` adds a second, orthogonal 2-port on the (½, ½) common-mode 

698 incidence — the exact even/odd decomposition, no cross-terms, so the 

699 differential behaviour is untouched. ``network_reduce. 

700 balanced_admittance_4x4`` is the closed 4×4 form of the same thing, kept 

701 as the oracle. A lossless line at exactly k·vf·λ/2 is an ordinary 

702 through-line here (the addendum below); real open-wire ``k1`` loss is 

703 still worth giving the exactly-λ/2 riser, but for its physics rather than 

704 to dodge a pole. 

705 

706 Addendum 2026-08-06 (issue #746): before the chain-matrix stamp, a 

707 lossless k·vf·λ/2 line RAISED — the 4×4 admittance form has a pole 

708 there — and designs carried length fudges to avoid it. That is gone; the 

709 half-wave case is now the best-conditioned length there is. 

710 

711 **No ``transposed`` flag**: with four explicit terminals a crossover (the 

712 Sterba's half-twist) is just wiring port B as ``(b2, b1)`` — visible in 

713 the design source. (A crossover flips only the differential sign; the CM 

714 block is symmetric under it.) 

715 

716 With ``zcomm=None`` the common mode is structurally open (the 4×4 is 

717 rank-2 by construction), so each terminal node must be 

718 common-mode-determinate from elsewhere — attached to a radiating wire 

719 (`PortOnWire`), driven, or wired to a non-BalancedLine branch. A node 

720 reachable *only* through CM-open BalancedLine terminals is rejected by 

721 `Network.__post_init__` (it would make MNA singular at solve time); a 

722 ``zcomm``-carrying BalancedLine is itself a common-mode return, so its 

723 terminals count as determinate. 

724 

725 Both engines stamp it through the shared `NetworkReducer` (a pure 

726 admittance block, no native NEC card — exactly like `TL`, `Shunt`, 

727 `Transformer`, `Admittance`), so PyNEC and momwire agree on it to 

728 MoM-basis tolerance and nec2++ serves as an independent oracle for the 

729 differential stamp. There is no native-card path: NEC-2 has no coupled- 

730 line card, but the reducer never needed one. (Physics validation of the 

731 differential *model* against real coupled structures — the isolation 

732 oracle and end-to-end TL Sterba — is issue #576.) 

733 """

736 a2: str 

737 b1: str 

738 b2: str

740 length: float 

741 vf: float = 1.0

826def two_wire_params( 

827 spacing: float, 

828 radius: float, 

829 radius2: float | None = None, 

830 *, 

831 insulation_radius: float | None = None, 

832 eps_r: float | None = None, 

833 fill: float | None = None, 

834) -> tuple[float, float]: 

835 """``(zdiff, vf)`` of a two-conductor line from its physical dimensions 

836 (issue #596). 

837 

838 ``spacing`` is centre-to-centre, ``radius``/``radius2`` are the conductor 

839 radii (``radius2=None`` → equal conductors); all lengths in metres, to 

840 match the rest of ``network.py``. Use it when you know the *line* — "#14 

841 wire, six inches apart" — rather than the number off a spool: 

842 

843 zdiff, vf = two_wire_params(0.1524, 0.000815) # ≈ 627 Ω, 1.0 

844 

845 **Bare conductors** are exact, from the general unequal-radius form 

846 

847 Z = (η₀/2π)·acosh((D² − a₁² − a₂²) / (2·a₁·a₂)) 

848 

849 which collapses to the textbook ``(η₀/π)·acosh(D/d)`` for equal radii 

850 (evaluated in that direct form when the radii match, which is both exactly 

851 the identity ``acosh(2x²−1) = 2·acosh(x)`` and better conditioned for 

852 closely-spaced wires). 

853 

854 **Insulation** is where the honesty caveats live, because a real balanced 

855 line is a *partial* dielectric fill — some of the field is in the plastic, 

856 most is in the air — and no closed form covers every construction. Two 

857 documented estimators, both reducing the result by ``√ε_eff`` (the 

858 inductance is unchanged: the jacket is not magnetic), so 

859 ``vf = 1/√ε_eff``: 

860 

861 - ``insulation_radius`` + ``eps_r`` — the **coaxial-shell** model: each 

862 conductor wears a jacket of outer radius ``b``, and the potential 

863 integral splits into a dielectric part ``(1/εᵣ)·ln(b/a)`` and an air part 

864 ``ln(D/b)``. Right for jacketed wire and for window line, where the 

865 conductors are round, jacketed, and separated by mostly air. It uses the 

866 wide-spacing (``D ≫ b``) logarithmic form for the *correction only* — the 

867 bare value it corrects stays exact — and it is refused outright when the 

868 jackets touch (``b₁ + b₂ ≥ D``), where the assumption of air between them 

869 is simply false. 

870 - ``fill`` + ``eps_r`` — the **mixing rule** ``ε_eff = 1 + fill·(εᵣ − 1)`` 

871 for the constructions the shell model can't describe: solid-web twinlead, 

872 or windowed line whose webbing you want to account for empirically. 

873 ``fill`` is the fraction of the field energy sitting in dielectric, and 

874 it is a fitted number, not a derived one (≈0.5 for solid twinlead, 

875 ≈0.15–0.25 for windowed line). Supply it when you have a nameplate ``vf`` 

876 to match; prefer the shell model when you don't. 

877 

878 Manufacturers' "450 Ω" and "300 Ω" are round numbers over a range of real 

879 constructions, so expect geometry-derived values to land within a few 

880 percent of a nameplate, not on it. When you know the nameplate ``vf``, 

881 it is better data than either estimator here. 

882 """ 

883 a1 = float(radius) 

884 a2 = float(radius if radius2 is None else radius2) 

885 d = float(spacing) 

886 if a1 <= 0 or a2 <= 0: 

887 raise ValueError("conductor radii must be positive") 

888 if d <= a1 + a2: 

889 raise ValueError( 

890 f"centre spacing {d} m must exceed the sum of the radii " 

891 f"({a1 + a2} m) — these conductors overlap" 

892 ) 

893 

894 if a1 == a2: 

895 z_bare = (ETA0 / math.pi) * math.acosh(d / (2.0 * a1)) 

896 else: 

897 z_bare = (ETA0 / (2.0 * math.pi)) * math.acosh( 

898 (d * d - a1 * a1 - a2 * a2) / (2.0 * a1 * a2) 

899 ) 

900 

901 eps_eff = 1.0 

902 if fill is not None: 

903 if eps_r is None: 

904 raise ValueError("fill needs eps_r (the insulation's permittivity)") 

905 if not 0.0 <= fill <= 1.0: 

906 raise ValueError(f"fill must be a fraction in [0, 1]; got {fill}") 

907 eps_eff = 1.0 + fill * (float(eps_r) - 1.0) 

908 elif insulation_radius is not None: 

909 if eps_r is None: 

910 raise ValueError("insulation_radius needs eps_r") 

911 b = float(insulation_radius) 

912 b1 = b2 = b 

913 if b1 <= a1 or b2 <= a2: 

914 raise ValueError( 

915 f"insulation radius {b} m must exceed the conductor radius" 

916 ) 

917 if b1 + b2 >= d: 

918 raise ValueError( 

919 f"the jackets touch at this spacing ({b1 + b2} m of insulation " 

920 f"across a {d} m gap): there is no air path between the " 

921 "conductors, so the coaxial-shell model does not apply. Give " 

922 "`fill` (with eps_r) for a solid-web line, or pass the " 

923 "nameplate zdiff/vf directly." 

924 ) 

925 er = float(eps_r) 

926 bare_terms = math.log(d / a1) + math.log(d / a2) 

927 clad_terms = ( 

928 math.log(b1 / a1) / er 

929 + math.log(d / b1) 

930 + math.log(b2 / a2) / er 

931 + math.log(d / b2) 

932 ) 

933 eps_eff = bare_terms / clad_terms 

934 

935 return z_bare / math.sqrt(eps_eff), 1.0 / math.sqrt(eps_eff)

939class FloatingBalun: 

940 """Floating-secondary transformer / link-coupling — the differential twin 

941 of `Transformer` (issue #589). Where `Transformer` spans both windings 

942 node-to-datum (a single-ended:single-ended balun *ratio*, but NOT the

944 **primary** (``primary`` node to the datum, e.g. a 50 Ω rig) and a 

945 genuinely **floating differential secondary** — the terminal pair 

946 ``(a, b)``, neither leg bonded to the datum. It is the one primitive that 

947 closes the balanced chain ``Driven → rig → FloatingBalun → balanced tuner 

948 → BalancedLine → antenna`` to a datum-locked source without injecting the 

949 common-mode current a balanced feed exists to avoid. 

950 

951 Reference topology: the Palstar BT1500A "double roller balanced tuner" 

952 places a 1:1 choke (current) balun at its 50 Ω input, converting the 

953 unbalanced coax to a balanced condition for the floating L-network; the 

954 balun is literally the first component and sits at the benign resistive 

955 input on purpose. `FloatingBalun(n=1)` is that element. 

956 

957 ``n`` is the primary→secondary ratio in the constitutive relation 

958 

959 v(a) − v(b) = n · v(primary) (v(primary) is vs. the datum) 

960 

961 so the *differential* impedance across the floating secondary is referred 

962 to the primary as ``Z_primary = Z_secondary / n²`` — a 1:1 balun (``n=1``, 

963 no loss) presents the balanced load impedance to the rig unchanged, and a 

964 4:1 current balun stepping a 200 Ω balanced load down to 50 Ω at the rig 

965 is ``n=2``. ``n = 1`` is a legal ideal element (no value is inverted); 

966 ``n = 0`` is rejected at stamp time (it would pin the secondary 

967 differential voltage to 0 — no physical balun does that). 

968

970 r — series winding resistance in Ω, referred to the secondary 

971 (constitutive row v_a − v_b − n·v_primary = r·j, j the 

972 secondary current); 

973 lmag — magnetizing / choke inductance in H, shunted across the primary 

974 node to the datum: at low frequency ωL_mag stops dwarfing the 

975 source and insertion loss rises, the classic balun low-end 

976 rolloff. This models the *balun's own* common-mode choking and 

977 is distinct from `BalancedLine.zcomm` (the *line's* CM path); 

978 qlmag — finite Q of the magnetizing branch (core loss), same 

979 convention as `Transformer.qlmag` / `ql` elsewhere. 

980 

981 Common-mode note: the constitutive row constrains only the secondary 

982 *differential* voltage; the secondary common mode ``(v_a + v_b)/2`` is 

983 genuinely floating (an isolated winding), and the element draws zero 

984 common-mode current (``I(a) = −I(b)`` at the element by construction). 

985 So the secondary pair needs a common-mode return from elsewhere — the 

986 antenna it feeds (a radiating structure grounds it), or a 

987 ``zcomm``-carrying `BalancedLine` — exactly like a CM-open `BalancedLine` 

988 terminal, and `Network.__post_init__` enforces this.

1202def _resolve_aliases(pairs, ports): 

1203 """Union-find over alias ``pairs``; returns a rename map name → canonical. 

1204 

1205 Canonical preference (deterministic): a real `PortOnWire` name beats any 

1206 virtual (its name is welded to geometry and must never be rewritten), 

1207 then top-level names beat instance-internal ones (fewer dots), then the 

1208 shorter / lexicographically-smaller name. Merging two real ports is an 

1209 error — two distinct geometry locations cannot be fused by naming.""" 

1210 parent = {} 

1211 

1212 def find(x): 

1213 parent.setdefault(x, x) 

1214 while parent[x] != x: 

1215 parent[x] = parent[parent[x]] 

1216 x = parent[x] 

1217 return x 

1218 

1219 for a, b in pairs: 

1220 ra, rb = find(a), find(b) 

1221 if ra != rb: 

1222 parent[ra] = rb 

1223 

1224 classes = {} 

1225 for n in parent: 

1226 classes.setdefault(find(n), []).append(n) 

1227 

1228 rename = {} 

1229 for members in classes.values(): 

1230 real = [n for n in members if isinstance(ports.get(n), (PortOnWire, PortAtEnd))] 

1231 if len(real) > 1: 

1232 raise ValueError( 

1233 f"aliases merge distinct geometry ports {sorted(real)} — " 

1234 "two real feed locations cannot be fused by naming" 

1235 ) 

1236 canon = min( 

1237 members, 

1238 key=lambda n: ( 

1239 0 if n in real else 1, 

1240 n.count("."), 

1241 len(n), 

1242 n, 

1243 ), 

1244 ) 

1245 for n in members: 

1246 if n != canon: 

1247 rename[n] = canon 

1248 return rename

1251def _series_rlc_impedance(r, l, c, omega, ql=None, qc=None): 

1252 """Series R + jωL + 1/(jωC). Any of r/l/c may be None (omitted term). 

1253 

1254 Finite component Q (issue #298): `ql` adds the coil's series loss 

1255 R_coil = ωL/Q_L; `qc` adds the capacitor's ESR = 1/(ωC·Q_C). Both are 

1256 frequency-dependent by construction — a fixed `r` cannot express them 

1257 across a sweep. None (default) = ideal component. 

1258 

1259 Q is treated as frequency-INDEPENDENT: R = ωL/Q is re-derived at each 

1260 solve frequency, so across a sweep R grows ∝ f. Physical truth for an 

1261 air-core HF coil sits between the two expressible models — skin effect 

1262 gives R ∝ √f (i.e. Q ∝ √f) — so constant Q overestimates loss above 

1263 the frequency where the quoted Q is true and underestimates below it, 

1264 while a fixed resistance (use plain `r` = ω_ref·L/Q for that) errs the 

1265 opposite way. At a single operating frequency, with Q quoted at that 

1266 frequency, all three agree. A √f reference-frequency model would slot 

1267 in here if sweep fidelity ever warrants it.""" 

1268 z = 0.0 + 0.0j 

1269 if r is not None: 

1270 z += r 

1271 if l is not None: 

1272 z += 1j * omega * l 

1273 if ql is not None: 

1274 z += omega * l / ql 

1275 if c is not None: 

1276 z += 1.0 / (1j * omega * c) 

1277 if qc is not None: 

1278 z += 1.0 / (omega * c * qc) 

1279 return z

1282def _parallel_rlc_admittance(r, l, c, omega, ql=None, qc=None): 

1283 """Parallel 1/R + 1/(jωL) + jωC. Any of r/l/c may be None (omitted term). 

1284 Trap dipoles use this: parallel-LC has Y → 0 at ω₀ = 1/√(LC), so the 

1285 branch opens at the trap's resonant frequency. 

1286 

1287 Finite Q (issue #298) lossifies each leg: the L leg becomes 

1288 1/(ωL/Q_L + jωL), the C leg 1/(1/(jωC) + 1/(ωC·Q_C)). A lossy trap no 

1289 longer opens completely — its resonant impedance tops out at the 

1290 textbook ≈ Q·ω₀L instead of ∞.""" 

1291 y = 0.0 + 0.0j 

1292 if r is not None: 

1293 y += 1.0 / r 

1294 if l is not None: 

1295 zl = 1j * omega * l 

1296 if ql is not None: 

1297 zl += omega * l / ql 

1298 y += 1.0 / zl 

1299 if c is not None: 

1300 if qc is not None: 

1301 y += 1.0 / (1.0 / (1j * omega * c) + 1.0 / (omega * c * qc)) 

1302 else: 

1303 y += 1j * omega * c 

1304 return y

1307def load_series_admittance(br, omega): 

1308 """Series-branch admittance y_load = 1/Z_load of a Load branch at ω. 

1309 

1310 This is the quantity the MNA termination stamp uses for a parallel-mode 

1311 Load (see network_reduce.NetworkReducer.apply_branches): it stays finite 

1312 exactly where Z_load blows up. 

1313 

1314 Parallel mode: y_load IS the parallel-LC tank admittance, 

1315 y = 1/R + 1/(jωL) + jωC, 

1316 which goes cleanly to 0 at ω₀ = 1/√(LC) — the trap-resonance open 

1317 circuit. No singularity: the "infinite impedance" only ever appeared 

1318 when we formed Z_load = 1/y and then took 1/Z_load again. 

1319 

1320 Series mode: y_load = 1/(R + jωL + 1/(jωC)); returns complex inf when 

1321 the series impedance is exactly 0 (series-LC short circuit), which the 

1322 caller treats as "no series element" (the wire is unbroken).""" 

1323 if br.z is not None: 

1324 # Fixed R+jX (issue #422): admittance 1/z, inf at z = 0 (a short). 

1325 return complex(float("inf"), 0.0) if br.z == 0 else 1.0 / complex(br.z) 

1326 if br.parallel: 

1327 return _parallel_rlc_admittance(br.r, br.l, br.c, omega, br.ql, br.qc) 

1328 z = _series_rlc_impedance(br.r, br.l, br.c, omega, br.ql, br.qc) 

1329 if z == 0: 

1330 return complex(float("inf"), 0.0) 

1331 return 1.0 / z

1334def load_impedance(br, omega): 

1335 """Effective series impedance of a Load branch at angular ω. 

1336 Series mode: Z = R + jωL + 1/(jωC). 

1337 Parallel mode: Z = 1 / (1/R + 1/(jωL) + jωC) — equals the parallel-LC 

1338 tank impedance, diverging at ω₀ = 1/√(LC) (the trap idiom). 

1339 

1340 Returns complex inf at parallel-LC resonance rather than raising — 

1341 Z→∞ is the physically-intended open circuit of a trap. Consumers that 

1342 stamp the load into a port-Y matrix should prefer 

1343 `load_series_admittance`, which avoids forming this infinity at all.""" 

1344 if br.z is not None: 

1345 return complex(br.z) # fixed R+jX, frequency-independent (issue #422) 

1346 if br.parallel: 

1347 y = _parallel_rlc_admittance(br.r, br.l, br.c, omega, br.ql, br.qc) 

1348 if y == 0: 

1349 return complex(float("inf"), 0.0) 

1350 return 1.0 / y 

1351 return _series_rlc_impedance(br.r, br.l, br.c, omega, br.ql, br.qc)

1455 def _validate_common_mode(self): 

1456 """A CM-open `BalancedLine` (``zcomm=None``) stamps only the 

1457 differential block, contributing nothing to its terminals' common 

1458 mode; a `FloatingBalun`'s secondary pair ``(a, b)`` is likewise 

1459 CM-floating — its constitutive row constrains only the differential 

1460 voltage and the element draws zero common-mode current (issue #589). 

1461 A node reachable ONLY through such terminals is common-mode floating, 

1462 which makes the MNA singular at solve time — raise a clear, 

1463 node-naming error here at build time instead. A node is 

1464 common-mode-determinate if it is a real `PortOnWire` or `PortAtEnd` 

1465 (an antenna-Y row grounds it), is driven by a source, is referenced by 

1466 any non-BalancedLine branch or by a ``zcomm``-carrying BalancedLine 

1467 (its CM block is itself a return), or is a `FloatingBalun` *primary* 

1468 — issues #575/#576/#589. 

1469 

1470 The primary is pinned by the element's CONSTITUTIVE ROW, not by any 

1471 path to the datum: ``v_a − v_b − n·v_p = r·j`` determines ``v_p`` once 

1472 the secondary pair is determinate (which the check above already 

1473 requires), and ``n = 0`` is rejected at stamp time so the coefficient 

1474 is never zero. The datum path one might reach for — the magnetizing 

1475 shunt ``G[p, p] += y_mag`` — is stamped only when the element declares 

1476 a magnetizing branch, and both `station.floating_balun` and 

1477 `station.balanced_l_tuner` default ``lmag_uH=None``, so for the common 

1478 ideal-balun case there is no such path at all (issue #660)."""

1480 b for b in self.branches if isinstance(b, BalancedLine) and b.zcomm is None 

1481 ] 

1482 fbaluns = [b for b in self.branches if isinstance(b, FloatingBalun)] 

1483 if not cm_open and not fbaluns:

1491 continue # CM-open line is not itself a common-mode return

1494 # docstring. The secondary pair is what we are checking FOR.
